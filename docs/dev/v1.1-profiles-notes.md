# 1.1.0 第四批（定稿）：多环境配置（profiles）— 实现记录

对应任务：`v1.1-TASK-4.md`（**取代** `v1.1-TASK-3.md` 的 MI50 专用设计）。
本记录描述实现，权威语义以任务文件为准。

## 1. 核心抽象

不再有 `deployMode`、`useMi50`、入口分流、互斥切换，也没有 MI50 特例。
**docker 与本地都只是"一套环境配置"（profile）**：

```
profiles: [ { id, name, type: "local" | "container", … } ]
activeProfileId: <string>
```

字段按 `type` 不同：

| type | 字段 |
|---|---|
| `local` | `strataDir` · `pythonPath` · `gpu`（可选，对应 `serve/server.py --gpu`）· `ggufDir` · `configFile`（可选覆盖）· `port` |
| `container` | `image` · `containerName` · `dataDir`（`/data`）· `ggufDir`（`/gguf`）· `port` |

同一张卡可以有多套配置；`gpu` 只是可选字段，配置不绑硬件。

## 2. UI 语义

- **配置页 = 管理配置**：列表（名称 + 类型徽标 + 选中标记）、编辑 / 删除、
  `+ 新建配置`；内联编辑器按类型只显示对应字段。运行中禁止改 / 删
  （按钮置灰，后端也拒绝）；至少保留一套；第一套自动命名 `default`。
- **停机页 = 选一套启动**：停机时显示配置单选列表，头部启动按钮用选中的一套；
  启动时把它写为 `activeProfileId`。
- **运行中**：状态头部显示当前配置 `名称 · 类型`。

## 3. 保留

- **首次启动**（第二批）：本机配置没有可用配置时，启动会先跑
  `setup.py --setup --yes --no-start [--gguf-dir <dir>]` 生成配置，再起
  `serve/server.py`，进度分四段（下载 → 转换 → 生成配置 → 加载）。
  容器配置由 entrypoint 以 `GGUF_DIR` + `STRATA_DATA` 自行 setup。
- 本机模式全部原有能力（配置读写、日志/指标、网络模式、源码更新管线）。

## 4. 移除

- `deployMode {local, docker}`、入口分流、互斥切换 + 停旧确认。
- 以镜像为锚的 build/重建更新管线、`routes/update.js` 的 docker 转发。
- MI50 专用勾选 / `useMi50` / `mi50DataDir` / `lib/gpu.js` / `test/mi50.test.js` /
  所有 `mi50.*` i18n 键。
- 旧 `test/docker.test.js`、`test/update-route.test.js`（已在第三批 WIP 删除）。

## 6. 向后兼容 / 零回归

没有存过 `profiles` 时，`readAllConfig` 用旧的扁平字段（`strataDir` /
`pythonPath` / `ggufDir` / `configFile` / `port` / `gpu`）合成一套名为
`default` 的本机配置，并把活动配置映射回这些扁平字段。于是：

- `routes/requests.js` 的 `resolvePort` / `resolveApiKey`、本机部署器、
  更新管线都无需感知 profiles。
- 既有的 `test/platform.test.js` 扁平字段用例、`test/firstrun.test.js`
  首启用例全部原样通过。
