# 1.1.0 第二批：补齐「首次启动」— 实现记录

对应任务：`v1.1-TASK-2.md`。在第一批（本机 / Docker 双模式，见
`v1.1-docker-notes.md`）之上补齐 **首次启动**：启动按钮同时覆盖
「已有配置 → 直接起」与「没有配置 → 先 setup 再起」。

## 1. 语义

- **配置页从「选已存在的配置文件」改成「指定 GGUF 模型目录」。**
  - 本机：`Strata 目录` · `Python 解释器` · `模型目录（GGUF）` ·
    `配置文件`（降级为可选覆盖，留空 = 自动用最新配置 / 自动生成）。
  - Docker：`数据目录（STRATA_DATA）` · `GGUF_DIR` · `镜像名` · `容器名`。
  - 两种模式都以「配置/数据放哪」+「模型从哪找」表达，目录概念同构。
- **首次启动 = 没有可用配置。**
  - 本机：目录下没有任何 `strata-*.json`（状态 `no-config`）。启动时跑
    `setup.py --setup --yes --no-start [--gguf-dir <模型目录>]`，生成配置后
    再起 `serve/server.py`。
  - Docker：容器不存在，或容器存在但卷上还没有配置。启动时由 App 用
    `STRATA_DATA=/data` + `GGUF_DIR=/gguf`（挂载 `<模型目录>:/gguf`）创建
    容器，`docker-entrypoint.sh` 自动跑 setup。
- **已有配置零回归。** `configFile` 留空时自动选最新的那份配置（setup.py
  每次启动会 `touch` 最近使用的配置，mtime 即「上次用过」信号），并把它持久化。
  于是「已有配置」走的是和第一批完全一样的直接启动路径，不进入 setup。

## 2. 进度分阶段

首次启动可能几分钟到几小时（下载 / 转换），所以进度分四段：
`下载模型 → 转换 / 准备模型 → 生成配置 → 加载模型`。

- 本机：后台跑 setup.py，按它自己的 `=== Step N: … ===` 标记切段
  （Step 5 = 下载，Step 6 = 准备），setup 退出后进入「生成配置」，随后
  `startService` 进入「加载」。
- Docker：`startService` 创建/启动容器后轮询容器日志，日志里的
  `Setting up … / Step 6 / Config:` 驱动分段；HTTP 能答即完成。
- 进度通过 `POST /start`（立即返回后台任务）+ `GET /start`（轮询）暴露，
  UI 复用 update 的遮罩，多了分阶段列表与「可能下载大文件」提示。
- 首次启动前会弹确认，写明「会先运行 setup 生成配置，可能需要下载 / 转换
  大模型（数十 GB）」。
